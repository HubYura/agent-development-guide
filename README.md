# SDD

Ця папка описує, як люди й AI-агенти змінюють проєкт. Основний принцип простий:

> Спочатку домовляємося, **що і навіщо** робимо. Потім описуємо, **як** це зробити. Лише після цього змінюємо код і перевіряємо результат.

## Швидкий старт

У корені свого проєкту створіть директорію `.docs`, перейдіть до неї та клонуйте цей репозиторій:

```bash
mkdir -p .docs
cd .docs
git clone git@github.com:HubYura/agent-development-guide.git
```

Після цього посібник буде доступний у `.docs/agent-development-guide`.

Якщо SSH-доступ до GitHub не налаштований, використайте HTTPS:

```bash
git clone https://github.com/HubYura/agent-development-guide.git
```

У основний CLAUDE.md/AGENTS.md на початку вставити 
```text
Інструкції для AI-агентів і людей, які змінюють цей репозиторій. Короткий
операційний зріз; повні правила — у `.docs/agent-development-guide/`.
```

## Один робочий цикл

```text
Запит → Спека → Погодження → План → Реалізація → Перевірка → Changelog/README
```

1. **Спека** фіксує проблему, межі та критерії приймання.
2. **План** розбиває погоджену спеку на малі перевірювані кроки.
3. **Реалізація** виконується строго в межах спеки й плану.
4. **Перевірка** доводить, що критерії приймання виконані.
5. **Changelog** пояснює, що змінилося для користувача або оператора.
6. **README** оновлюється, якщо змінилися запуск, конфігурація, API чи архітектура.

## Де зберігати робочі документи

Коли почнеться розробка, створюйте:

```text
.docs/
├── specs/      # Погоджені вимоги
├── plans/      # Плани реалізації
└── changes/    # Детальні записи про завершені зміни
```

Назви файлів:

```text
specs/SPEC-2026-001-readiness-healthcheck.md
plans/PLAN-2026-001-readiness-healthcheck.md
changes/2026-08-05-readiness-healthcheck.md
```

Спека та план однієї зміни повинні мати однаковий номер.

## Рівні процесу

| Зміна                                          | Що потрібно                                                          |
| ---------------------------------------------- | -------------------------------------------------------------------- |
| Друкарська помилка, форматування               | Короткий опис і перевірка                                            |
| Звичайна функція або виправлення               | Спека, план, тести, changelog за потреби                             |
| API, база даних, auth, платежі, черги, безпека | Повна спека, план, rollout, rollback, спостережуваність і погодження |

Якщо є сумнів — використовуйте повний процес.
