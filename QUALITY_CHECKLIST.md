# Контрольний список якості

Цей список використовується перед початком і перед завершенням кожної нетривіальної зміни.

## Definition of Ready

Роботу можна починати, якщо:

- [ ] проблема і користувач результату зрозумілі;
- [ ] scope та non-goals записані;
- [ ] спека має статус `Approved`;
- [ ] критерії приймання конкретні й перевірювані;
- [ ] відомі зміни API, даних, конфігурації та залежностей;
- [ ] описані помилки й граничні випадки;
- [ ] для ризикової зміни є rollout, rollback і спостережуваність;
- [ ] план містить точні файли, кроки та команди перевірки;
- [ ] немає невирішених питань, що змінюють архітектуру або поведінку.

## Перевірка спеки

- [ ] Заголовок і короткий summary пояснюють зміну без додаткового контексту.
- [ ] Терміни використовуються однаково в тексті, API та коді.
- [ ] Кожна ціль має хоча б один критерій приймання.
- [ ] Кожен критерій має очікуваний результат, а не суб'єктивне слово.
- [ ] Не-цілі захищають від розширення scope.
- [ ] Немає прихованих рішень у секції відкритих питань.
- [ ] Безпека, приватність, idempotency та concurrency розглянуті там, де це потрібно.

## Перевірка плану

- [ ] План посилається на погоджену спеку й ту саму ревізію.
- [ ] Кроки мають правильний порядок і явні залежності.
- [ ] Названі конкретні файли, а не абстрактні «модулі».
- [ ] Тести створюються до або разом із поведінкою.
- [ ] Команди перевірки можна скопіювати й виконати.
- [ ] Для міграцій описані forward і rollback дії.
- [ ] План не містить робіт поза scope спеки.

## Definition of Done

Зміна завершена, якщо:

- [ ] усі критерії приймання виконані й мають докази;
- [ ] реалізація не вийшла за межі погодженого scope;
- [ ] lint, форматування і typecheck успішні;
- [ ] unit, integration та e2e-тести виконані в доречному обсязі;
- [ ] негативні сценарії перевірені;
- [ ] міграції протестовані;
- [ ] секрети та персональні дані не потрапили в код або логи;
- [ ] OpenAPI, `.env.example`, README та runbook оновлені за потреби;
- [ ] changelog доданий за потреби;
- [ ] diff перечитано, тимчасові файли й debug-логування видалені;
- [ ] відомі обмеження та ризики явно записані;
- [ ] для командної роботи handoff прийнятий, а інтегратор повторно запустив заявлені перевірки;
- [ ] спека й план переведені у `Done`.

## Фінальний звіт агента

Агент завершує роботу коротким звітом:

```text
Змінено:
- <файл або компонент>: <результат>

Перевірено:
- <команда>: PASS

Не перевірено:
- <що саме і чому>

Ризики/обмеження:
- <залишковий ризик або «немає відомих»>
```
